# V1.13 Matched OpenMC Benchmark Specification

## 1. Purpose

V1.13 establishes the first matched deterministic-versus-Monte-Carlo photon-shielding benchmark in the Shielding Attenuation project.

The release must demonstrate that one backend-independent physical shielding scenario can be evaluated by:

1. the existing deterministic photon-shielding calculator; and
2. an OpenMC fixed-source photon-transport backend.

Both calculations must use the same:

* source definition;
* photon energy and emission intensity;
* source activity;
* shielding material;
* shielding dimensions;
* evaluation region;
* dry-air response-coefficient basis; and
* reported physical units.

The benchmark is intended to verify the deterministic model against an independent Monte Carlo transport calculation. It is not experimental validation.

---

## 2. V1.13 Scope

V1.13 includes:

* scenario schema version 1.1;
* a new `fixed_shield_response` calculation mode;
* deterministic response calculation for completed fixed shields;
* deterministic spherical-shell averaging;
* OpenMC-independent settings and result models;
* an isolated OpenMC backend;
* a one-layer Lead development case;
* an official one-layer Lead production benchmark;
* an energy-resolved photon spectrum tally;
* a direct collision-air-kerma response tally;
* Monte Carlo statistical uncertainty;
* automatic result parsing and normalization;
* deterministic and OpenMC comparison metrics;
* processed JSON and CSV result artifacts;
* one polished benchmark figure; and
* a V1.13 validation report.

V1.13 does not include:

* multilayer shielding;
* material optimization;
* layer-order studies;
* variance-reduction methods;
* final shield-container design;
* experimental validation;
* a GUI;
* universal buildup-factor fitting; or
* a complete engineering book.

## 3. Scenario Architecture

### 3.1 Schema version

The fixed-shield benchmark uses:

```text
schema_version = "1.1"
```

Schema version 1.0 must remain supported without modification to existing scenario files.

### 3.2 Calculation modes

V1.13 supports two scenario calculation modes:

```text
material_optimization
fixed_shield_response
```

### 3.3 Material-optimization mode

A `material_optimization` scenario:

* requires at least one candidate material;
* requires a response target;
* requires engineering constraints;
* requires an optimization objective;
* may include optimization weights when balanced optimization is selected; and
* must not contain fixed shielding layers.

### 3.4 Fixed-shield-response mode

A `fixed_shield_response` scenario:

* requires at least one fixed shielding layer;
* uses the ordered layers stored in the geometry;
* does not require candidate materials;
* does not perform material ranking;
* does not require engineering constraints;
* does not require an optimization objective;
* calculates the response of the completed physical shield; and
* supplies the same physical source and geometry to the deterministic and OpenMC backends.

A response target is not required for the V1.13 benchmark. The purpose of this mode is response calculation and code-to-code comparison rather than design acceptance.

## 4. Frozen Source Definition

### 4.1 Isotope

The official benchmark source is Cs-137 using the existing project isotope library.

### 4.2 Activity

```text
Activity = 3.70 × 10^10 Bq
```

This is equivalent to 1.00 Ci.

### 4.3 Selected photon line

The benchmark uses the same selected major photon line already represented by the deterministic source library:

```text
Photon energy = 0.661657 MeV
Emission intensity = 0.851 photons per decay
```

### 4.4 Physical photon emission rate

The physical photon emission rate is:

```text
photon rate = activity × emission intensity
```

Therefore:

```text
photon rate
= (3.70 × 10^10 decays/s)(0.851 photons/decay)
= 3.1487 × 10^10 photons/s
```

OpenMC source particles represent samples from this photon source. OpenMC tally results are normalized per source particle and are later scaled by the physical photon emission rate.

### 4.5 Source geometry

The source is:

* a point source;
* centered at `(0.0, 0.0, 0.0)` cm;
* isotropic; and
* monoenergetic at 661,657 eV.

The source is located inside a vacuum cavity.

## 5. Frozen Production Geometry

The official V1.13 production benchmark uses concentric spherical geometry.

### 5.1 Source cavity

```text
Source-cavity radius = 1.0 cm
Material = vacuum
```

### 5.2 Lead shield

```text
Material = Lead
Density = 11.34 g/cm³
Inner radius = 1.0 cm
Thickness = 5.0 cm
Outer radius = 6.0 cm
```

The Lead definition must be created from the project material library and translated into an OpenMC material by the OpenMC backend.

### 5.3 Inner transport region

The region between the Lead shield and the evaluation shell is vacuum.

```text
Inner vacuum radius range:
6.0 cm to 99.5 cm
```

### 5.4 Evaluation shell

The scoring region is a thin spherical vacuum shell centered at an evaluation radius of 100 cm.

```text
Evaluation-shell inner radius = 99.5 cm
Evaluation-shell outer radius = 100.5 cm
Evaluation-shell thickness = 1.0 cm
```

The evaluation shell is vacuum rather than physical air.

The shell is a scoring region used to estimate photon fluence. Collision air kerma is calculated afterward by folding the photon fluence with the project’s dry-air mass energy-absorption coefficients.

### 5.5 Outer transport region

The region outside the evaluation shell remains vacuum.

```text
Outer vacuum radius range:
100.5 cm to 110.0 cm
```

### 5.6 Boundary

```text
Outer boundary radius = 110.0 cm
Boundary type = vacuum
```

Particles crossing this boundary leave the model.

## 7. Matched Deterministic Observable

### 7.1 Reason for shell averaging

The existing deterministic calculator reports photon fluence and collision air kerma at a point evaluation radius.

An OpenMC cell flux tally over the evaluation shell represents a volume-integrated track-length quantity. After division by the shell volume, it represents the volume-averaged fluence throughout the shell.

The formal deterministic-versus-OpenMC comparison must therefore use a deterministic shell-volume average rather than only the deterministic point value at 100 cm.

### 7.2 Evaluation-shell volume

For shell inner radius `r1` and outer radius `r2`:

```text
V_shell = (4π/3)(r2³ - r1³)
```

For V1.13:

```text
r1 = 99.5 cm
r2 = 100.5 cm
```

### 7.3 Deterministic uncollided shell-average fluence rate

For physical photon emission rate `S` and narrow-beam shield transmission `T`:

```text
Φ_dot(r) = ST / (4πr²)
```

The volume-averaged fluence rate over the spherical shell is:

```text
average Φ_dot
= (1 / V_shell)
  integral from r1 to r2 of
  [ST / (4πr²)](4πr² dr)
```

which simplifies to:

```text
average Φ_dot
= ST(r2 - r1) / V_shell
```

The formal OpenMC comparison uses this shell-averaged deterministic value.

### 7.4 Point response

The deterministic point response at exactly 100 cm may also be reported because it is familiar and useful for engineering interpretation.

It must be labeled as a point response and must not be substituted for the matched shell-average observable.

### 7.5 Deterministic collision air kerma

For each photon line:

```text
collision air-kerma rate
= photon energy-fluence rate
  × dry-air mass energy-absorption coefficient
```

The V1.13 deterministic result must report:

* shell-averaged uncollided photon fluence rate;
* shell-averaged uncollided collision air-kerma rate;
* point uncollided collision air-kerma rate at 100 cm;
* G-P exposure-buildup-adjusted shell-average collision air kerma, when available;
* G-P buildup factor; and
* calculation warnings.

The G-P result is a deterministic comparison estimate. It is not assumed to match OpenMC.

## 8. OpenMC Transport Definition

### 8.1 Run mode

OpenMC will run in fixed-source mode.

### 8.2 Particle transport

The model will explicitly enable photon transport.

### 8.3 Electron treatment

The production calculation will explicitly use:

```text
electron treatment = thick-target bremsstrahlung
```

The implementation must not rely on an undocumented or implicit default.

### 8.4 Atomic relaxation

Atomic relaxation will be explicitly enabled.

This allows the model to retain fluorescence and other relaxation photons produced following inner-shell interactions.

### 8.5 Photon energy cutoff

The production photon cutoff will be:

```text
1,000 eV
```

This matches the lower boundary of the project dry-air mass energy-absorption coefficient library.

Photons below this energy are not included in the V1.13 air-kerma response.

### 8.6 Continuous-energy mode

The benchmark uses continuous-energy photon transport.

### 8.7 Cross-section library

The exact cross-section library path and identifying information must be recorded in the run manifest.

The physical scenario JSON must not contain a machine-specific cross-section path.

## 9. OpenMC Tallies

V1.13 uses two OpenMC tallies in the evaluation shell.

### 9.1 Tally 1: Energy-resolved photon spectrum

Filters:

* evaluation-shell cell filter;
* photon particle filter; and
* incident-energy filter.

Score:

```text
flux
```

Purpose:

* show the surviving 661.657 keV source-energy peak;
* show scattered lower-energy photons;
* show fluorescence features where resolved;
* provide the V1.13 spectrum figure;
* support independent post-run response folding; and
* support future V1.14 energy-discretization studies.

The production energy range must cover at least:

```text
1,000 eV to 700,000 eV
```

The exact bin boundaries belong to the OpenMC production settings profile.

### 9.2 Tally 2: Direct collision-air-kerma response

Filters:

* evaluation-shell cell filter;
* photon particle filter; and
* an energy-function filter representing the dry-air collision-air-kerma response.

Score:

```text
flux
```

The response function is proportional to:

```text
photon energy
× dry-air mass energy-absorption coefficient
× unit-conversion factor
```

The response function must use the same dry-air coefficient library and interpolation behavior as the deterministic V1.12 calculation.

The direct response tally must provide:

* mean response per source particle;
* standard deviation per source particle; and
* relative statistical uncertainty.

The direct tally is the authoritative OpenMC collision-air-kerma result.

### 9.3 Spectrum-folded cross-check

The energy-resolved spectrum will also be folded with the dry-air response function after the OpenMC run.

The spectrum-folded result is an independent numerical cross-check of the direct response tally.

It is not used as the authoritative uncertainty estimate because energy-bin covariance is not directly preserved by independently summing reported bin uncertainties.

## 10. OpenMC Numerical Settings

OpenMC numerical settings are not part of the physical shielding scenario.

They will be stored in separate profile files:

```text
config/openmc/v113_development.json
config/openmc/v113_production.json
```

These files will be loaded into a validated OpenMC-independent Python dataclass.

Expected settings include:

* particles per batch;
* number of batches;
* random seed;
* thread count;
* evaluation-shell thickness;
* outer boundary radius;
* energy-bin boundaries;
* electron treatment;
* atomic-relaxation setting;
* photon energy cutoff; and
* requested statepoint batches.

The physical geometry values stored in an execution profile must agree with the benchmark specification. They must not silently override the physical scenario.

The final design may instead move evaluation-shell and boundary geometry into a dedicated backend-observation specification if this produces a cleaner architecture during implementation.

## 11. Normalization and Units

### 11.1 Raw OpenMC flux tally

The raw track-length flux tally is normalized per simulated source particle and integrated over the spatial tally region.

### 11.2 Volume normalization

The raw tally mean and standard deviation must be divided by the evaluation-shell volume:

```text
fluence per source particle
= raw track-length tally / shell volume
```

The resulting unit is:

```text
photons/cm² per source particle
```

### 11.3 Physical source-rate scaling

The volume-normalized value is multiplied by:

```text
3.1487 × 10^10 photons/s
```

The resulting physical photon fluence-rate unit is:

```text
photons/cm²/s
```

### 11.4 Air-kerma response

After applying the energy-dependent dry-air response function, the canonical collision-air-kerma-rate unit is:

```text
Gy/s
```

The primary engineering display unit is:

```text
µGy/h
```

### 11.5 Uncertainty scaling

Every multiplicative normalization applied to the tally mean must also be applied to its standard deviation.

Relative uncertainty is:

```text
relative uncertainty
= standard deviation / mean
```

The relative uncertainty is dimensionless and is unchanged by deterministic multiplicative normalization.

## 12. Comparison Quantities

The V1.13 comparison will report three principal response values:

1. deterministic uncollided shell-average collision air kerma;
2. deterministic G-P-adjusted shell-average collision air kerma; and
3. OpenMC total shell-average collision air kerma.

### 12.1 Difference from uncollided deterministic response

```text
relative difference from uncollided
= (OpenMC - deterministic uncollided)
  / deterministic uncollided
```

### 12.2 Difference from G-P deterministic response

```text
relative difference from G-P
= (OpenMC - deterministic G-P)
  / deterministic G-P
```

This quantity is reported only when the deterministic G-P response is available.

### 12.3 Observed Monte Carlo buildup ratio

```text
B_MC
= OpenMC total collision air kerma
  / deterministic uncollided collision air kerma
```

This quantity must be labeled:

```text
Observed Monte Carlo buildup ratio for this benchmark scenario
```

It is not a general material buildup coefficient and must not be reused as one.

## 13. Statistical Requirements

### 13.1 Development case

The development case must produce:

* a positive spectrum tally;
* a positive direct-response tally;
* a finite standard deviation;
* a finite relative uncertainty; and
* a readable statepoint file.

No strict uncertainty target is required for the development case.

### 13.2 Production case

The official production benchmark must achieve:

```text
required relative uncertainty ≤ 5%
preferred relative uncertainty ≤ 2%
```

The requirement applies to the direct OpenMC collision-air-kerma response tally.

If the production result exceeds 5%, the number of particle histories must be increased before the result is accepted.

### 13.3 Direct-versus-folded response agreement

The direct response tally and spectrum-folded response must agree within:

```text
2% relative difference
```

If they do not, the energy-bin structure, response interpolation, normalization, and unit conversion must be investigated before accepting the benchmark.

### 13.4 Deterministic-versus-OpenMC agreement

V1.13 does not impose a fixed pass/fail agreement tolerance between:

* deterministic uncollided response;
* deterministic G-P response; and
* OpenMC response.

Their differences are physical and methodological results that must be reported and interpreted rather than forced to agree.

## 19. Interpretation and Terminology

The project should describe V1.13 as:

```text
Deterministic photon-shielding verification and benchmarking against
OpenMC fixed-source Monte Carlo photon transport.
```

The project should not describe V1.13 as:

```text
experimental validation
```

unless future work compares the software against measured radiation data.

The OpenMC result represents the benchmark’s total transported photon response under the documented OpenMC physics settings.

The deterministic uncollided result represents narrow-beam Beer–Lambert attenuation.

The deterministic G-P result represents a homogeneous-shield exposure-buildup approximation.

Disagreement between these methods is a result to investigate and explain, not automatically a software failure.
